## Versioning

github-sts follows [Semantic Versioning](https://semver.org). While the project is pre-1.0:

- **Minor (`0.X.0`)**: new features and may contain breaking changes; read release notes before upgrading.
- **Patch (`0.0.X`)**: bug fixes and non-breaking improvements.

Breaking changes are called out at the top of each release's notes on GitHub.

## Compatibility

| Component | Compatibility |
|---|---|
| Go client (`client/`) | Same major/minor as the server; minor version bumps may add new methods but won't remove existing ones pre-1.0. |
| Trust policy schema | Backwards-compatible additions only. New required fields (e.g. `audience`) are introduced behind a deprecation window: see release notes. |
| Configuration (YAML / env) | Backwards-compatible additions only. Removed/renamed fields emit a startup warning for one minor version before removal. |
| HTTP API (`/sts/exchange`) | Stable request/response shape. New optional parameters and error `code`s may be added; existing ones won't change meaning. |
